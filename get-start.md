# DLL Flowlyzer - Getting Started Guide

## Overview

DLL Flowlyzer is a comprehensive DataLink Layer Network Flow Analyzer that extracts **343+ features** from network PCAP files, focusing on Layer 2 protocols while supporting full Layer 3 analysis. It's designed for network security analysis, attack detection, and machine learning applications with **automatic visualization generation** and **real-time CSV batching**.

## Key Features
- **343+ Features**: Comprehensive feature extraction including Layer 2 protocols (STP, CDP, ARP, DHCP, LLDP, etc.)
- **Multi-Folder Processing**: Handles organized datasets with per-folder attack labeling
- **JSON Attack Labeling**: Advanced attack detection with time-based, MAC-based, and protocol-specific rules
- **Real-Time CSV Batching**: Prevents data loss with configurable batch sizes
- **Automatic Visualizations**: 7+ charts generated by default (no --plot flag needed)
- **Memory Optimization**: Intelligent memory management for large datasets
- **Comprehensive Vendor Database**: 500+ MAC vendor identification

## Initial Setup

### 1. Prerequisites
- **Python**: 3.7 or higher (3.8+ recommended)
- **Memory**: Minimum 4GB RAM (8GB+ recommended for large datasets)
- **Storage**: Adequate space for output files and visualizations
- **OS**: Linux, macOS, or Windows

### 2. Clone and Setup Virtual Environment
```bash
# Clone the repository (if not already done)
git clone <repository_url>
cd DLLFlowlyzerV1

# Create and activate virtual environment
python3 -m venv .venv

# Activate virtual environment
# On Linux/macOS:
source .venv/bin/activate
# On Windows:
# .venv\Scripts\activate

# Verify Python version
python --version
```

### 3. Install Dependencies
```bash
# Upgrade pip
pip install --upgrade pip

# Install required packages
pip install -r requirements.txt

# Verify installation
python -m src.flowlyzer.main --help
```

### 4. Prepare Input Directory
```bash
# Create input directory
mkdir -p Input

# Copy your PCAP files to Input directory
# cp /path/to/your/capture.pcap Input/
```

## Basic Usage Scenarios

### Scenario 1: Single PCAP File Analysis
**Use Case**: Analyze a single network capture file
```bash
# Basic analysis
python -m src.flowlyzer.main -i Input/capture.pcap

# With custom output directory
python -m src.flowlyzer.main -i Input/capture.pcap -o MyResults

# With verbose logging
python -m src.flowlyzer.main -i Input/capture.pcap --log-level DEBUG
```

### Scenario 2: Multiple PCAP Files in Directory
**Use Case**: Analyze all PCAP files in a single directory
```bash
# Process all PCAP files in Input directory
python -m src.flowlyzer.main -i Input/

# Separate Layer 2 and Layer 3 analysis
python -m src.flowlyzer.main -i Input/ --separate-layers

# With performance optimization
python -m src.flowlyzer.main -i Input/ --workers 8 --feature-threads 6
```

### Scenario 3: Multi-Folder Processing (Daily Captures)
**Use Case**: Process multiple days of network captures, each day split into multiple files

**Directory structure:**
```
Captures/
├── Day1/
│   ├── morning_01.pcap
│   ├── morning_02.pcap
│   └── morning_03.pcap
├── Day2/
│   ├── afternoon_01.pcap
│   ├── afternoon_02.pcap
│   └── afternoon_03.pcap
└── Day3/
    ├── evening_01.pcap
    └── evening_02.pcap
```

```bash
# Basic multi-folder processing
python -m src.flowlyzer.main -i Captures/ --multi-folder

# With layer separation
python -m src.flowlyzer.main -i Captures/ --multi-folder --separate-layers

# High-performance multi-folder processing
python -m src.flowlyzer.main -i Captures/ --multi-folder \
  --workers 8 --feature-threads 6 --folder-threads 2

# Quiet mode with custom output
python -m src.flowlyzer.main -i Captures/ --multi-folder \
  -o DailyAnalysis --quiet
```

## Attack Detection Scenarios

### Scenario 4: IP-Based Attack Detection
**Use Case**: Detect attacks from known malicious IP addresses
```bash
# Single attacker IP
python -m src.flowlyzer.main -i Input/ \
  --label-ip "192.168.1.100=ARP Spoofing"

# Multiple attacker IPs
python -m src.flowlyzer.main -i Input/ \
  --label-ip "192.168.1.100=ARP Spoofing" \
  --label-ip "192.168.1.200=DHCP Starvation"
```

### Scenario 5: MAC-Based Attack Detection
**Use Case**: Detect attacks from specific MAC addresses
```bash
# MAC-based labeling
python -m src.flowlyzer.main -i Input/ \
  --label-mac "aa:bb:cc:dd:ee:ff=CAM Flood" \
  --label-mac "11:22:33:44:55:66=ARP Poisoning"
```

### Scenario 6: Time-Based Attack Detection
**Use Case**: Label network traffic during known attack periods
```bash
# Time-based attack labeling
python -m src.flowlyzer.main -i Input/ \
  --label-time "10:00 AM-11:30 AM=DHCP Starvation" \
  --label-time "2:15 PM-3:45 PM=STP Attack"
```

### Scenario 7: Per-Folder Attack Labeling
**Use Case**: Different attack types for different days/sessions

**Setup per-folder labeling with JSON (New!):**
```bash
# Create JSON labeling files for each folder
cat > Captures/Day1/labeling.json << 'EOF'
{
  "layer_2_only": true,
  "mac_labels": [
    {"mac": "aa:bb:cc:dd:ee:ff", "label": "ARP Spoofing Attack"}
  ]
}
EOF

cat > Captures/Day2/labeling.json << 'EOF'
{
  "time_labels": [
    {"time_range": "10:00-12:00", "label": "DHCP Starvation Attack"}
  ]
}
EOF
# Day3 has no labeling file (all flows will be "Benign")

# Run multi-folder analysis
python -m src.flowlyzer.main -i Captures/ --multi-folder
```

**Setup per-folder labeling with text files (Traditional):**
```bash
# Create folder-specific labeling files
echo "mac: aa:bb:cc:dd:ee:ff ARP Spoofing" > Captures/Day1/labeling.txt
echo "10:00 AM - 12:00 PM : DHCP Attack" > Captures/Day2/labeling.txt
# Day3 has no labeling.txt (all flows will be "Benign")

# Run multi-folder analysis
python -m src.flowlyzer.main -i Captures/ --multi-folder
```

### Scenario 8: Configuration File-Based Labeling
**Use Case**: Complex labeling rules defined in configuration files

**Create labeling_config.json:**
```json
{
  "ip_attacks": [
    {
      "label": "ARP Spoofing", 
      "ips": ["192.168.1.100", "192.168.1.200"]
    }
  ],
  "mac_attacks": [
    {
      "label": "CAM Flood",
      "macs": ["aa:bb:cc:dd:ee:ff"]
    }
  ],
  "time_attacks": [
    {
      "label": "STP Attack",
      "time_ranges": [{"start": "9:00 AM", "end": "10:30 AM"}]
    }
  ]
}
```

```bash
# Use configuration file
python -m src.flowlyzer.main -i Input/ --label-config labeling_config.json
```

**Use Case**: Process flows and save results in real-time to prevent data loss
```bash

python -m src.flowlyzer.main -i Input/ --csv-batch-size 10

# Large batches for better performance (200 flows)

```

### Scenario 10: High-Performance Processing
**Use Case**: Maximum performance for large datasets with 343+ features
```bash

  --workers 12 --feature-threads 8 --max-flows 100000 \
  --queue-size 200000 --batch-size 100 --csv-batch-size 100

  --workers 8 --feature-threads 8 --folder-threads 3 \
```

```bash

python -m src.flowlyzer.main -i Input/ \
  --batch-size 15 --csv-batch-size 12 --workers 2 --max-flows 5000

python -m src.flowlyzer.main -i LargeFile.pcap \
  --batch-size 10 --csv-batch-size 8 --workers 1 --feature-threads 1 \
  --max-flows 2000 --flow-timeout 300

# Very frequent CSV updates for memory-constrained systems:
python -m src.flowlyzer.main -i Input/ \
  --csv-batch-size 5 --batch-size 10 --workers 1 --max-flows 1000

# Legacy approach (disable optimizations):
python -m src.flowlyzer.main -i Input/ --disable-batching \
  --workers 2 --feature-threads 2 --max-flows 10000
```

## Output Files Explanation

After running any command, you'll find these files in your output directory:

### Basic Output Files (NEW Format!)
- `analysis_features_combined_YYYYMMDD_HHMMSS.csv` - Main features with **343+ columns**
- `log.txt` - Processing log with real-time batch updates

### With Layer Separation  
- `features_combined_YYYYMMDD_HHMMSS.csv` - All flows with full features
- `features_layer2_YYYYMMDD_HHMMSS.csv` - Pure Layer 2 flows only  
- `features_layer3_YYYYMMDD_HHMMSS.csv` - Layer 3+ flows only

### Comprehensive Visualizations (7 Files)
- `protocol_statistics_*.png` - Protocol distribution (TCP, UDP, STP, CDP, ARP, LLDP, etc.)
- `layer2_analysis_*.png` - Detailed Layer 2 protocol breakdown
- `layer2_heatmap_analysis_*.png` - Feature correlation heatmap
- `flow_statistics_*.png` - Flow duration and packet size analysis
- `attack_analysis_*.png` - Attack vs benign traffic visualization
- `feature_correlation_*.png` - Full feature correlation matrix
- `analysis_statistics_*.csv` - Summary statistics and protocol counts

### Multi-Folder Output Structure
```
Results/
├── Day1/
│   ├── Day1_features_YYYYMMDD_HHMMSS.csv
│   └── [visualization files]
├── Day2/
│   ├── Day2_features_YYYYMMDD_HHMMSS.csv  
│   └── [visualization files]
└── log.txt
```
